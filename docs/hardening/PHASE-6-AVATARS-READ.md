# المرحلة 6: تقييد قراءة مجلد الصور (`avatars: read`)

**التاريخ:** 3/11/2026
**الفرع:** `hardening/avatars-read-policy` (فوق `hardening/photo-db-guards`).
**الحالة:** migration **مكتوبة ومختبرة، ولم تُطبَّق على أي مشروع**. لا تعديل على كود التطبيق ولا على `main` أو `staging` أو الإنتاج.

## 1. المشكلة

السياسة الحالية (من `20261024010000_photos_admin.sql`):
```sql
create policy "avatars: read" on storage.objects for select using (bucket_id = 'avatars');
```
- بلا دور ولا شرط مجلد، فتنطبق على **الجميع**، والزائر بمفتاح التطبيق العام منهم.
- **أي شخص** يستطيع عبر واجهة التخزين (list):
  - سرد جذر المجلد، فيحصل على **أرقام حسابات كل من لديه صورة**؛
  - سرد مجلد أي مستخدم، فيحصل على **أسماء كل ملفاته**.
- **الأثر:**
  - **تجاوز المراجعة:** صورة المعلم أو المعهد **المنتظرة أو المرفوضة** غير معروضة في التطبيق، لكن اسمها يُعرف بالسرد، ثم تُفتح برابطها العام.
  - **صور الطلاب والأهل** (وقد يكونون قاصرين) يمكن حصرها دون معرفة روابطها.
  - **قائمة أرقام الحسابات.**

## 2. الإصلاح

**Migration:** `supabase/migrations/20261104000000_avatars_read_own.sql`
```sql
drop policy if exists "avatars: read" on storage.objects;
create policy "avatars: read own" on storage.objects for select to authenticated
  using (bucket_id = 'avatars' and (storage.foldername(name))[1] = auth.uid()::text);
```
- **من يقرأ:** المستخدم المسجَّل فقط، وفي **مجلده وحده**، وهي القاعدة نفسها المطبَّقة أصلاً على الرفع والاستبدال والحذف.
- **ما لا يتأثر:**
  - **الروابط العامة:** لا تمر بهذه السياسات، فالـ bucket يبقى عاماً والصور المعتمدة تظهر كما هي.
  - **تنظيف الصور** (`tidyPhotos`): يسرد ويحذف مجلد صاحبه فقط.
  - **الرفع** (`upsert: false`): لا يحتاج القراءة، والحذف يحتاجها لصفوف المالك فقط، وهي مسموحة.
  - **فحص الصحة** (`lib/health.ts`): يسرد الجذر، فيحصل على قائمة فارغة **بلا خطأ**، فيبقى «متاحاً».
  - **المدير:** لا يسرد الملفات. يراجع عبر الروابط العامة المحفوظة في التعديلات المنتظرة.
- لا تغيير بيانات، ولا كود تطبيق.

## 3. التراجع

`supabase/rollback/20261104000000_avatars_read_own.down.sql` يعيد السياسة القديمة كما كانت. بعده على مشروع مستضاف يُحذف سجل الـ migration، والأمر مكتوب في رأس الملف.

## 4. التطبيق على staging فقط (بعد موافقتك، لم يُنفَّذ)

`supabase/staging/apply_20261104000000_avatars_read_own.sql`: معاملة واحدة، **ترفض** إذا:
1. لم تكن قاعدة البيانات هي classi-staging (`system_identifier` = 7702070854497379551)؛
2. لم يكن الـ marker `deploy_env='staging'` موجوداً؛
3. كانت الـ migration مسجَّلة مسبقاً؛
4. لم تكن migration المرحلة 6 السابقة (`20261103010000`) مطبَّقة؛
5. لم تكن السياسة القديمة موجودة (حالة غير متوقعة).

الجزء بين علامتي BEGIN/END هو ملف الـ migration نفسه **حرفياً**، ويتحقق CI من ذلك.

**مُختبر محلياً:**
- الملف الحقيقي على قاعدة محلية: «refusing: not the classi-staging database»، ولم يتغيّر شيء.
- نسخة مؤقتة غُيِّر فيها رقم القاعدة فقط إلى المحلي:
  - طُبِّقت مرة واحدة وسجّلت نفسها؛
  - رفضت في المرة الثانية: «already recorded»؛
  - رفضت حين لم يكن الـ marker «staging».

**ما تثبته `avatars_read_test`:**
1. **الزائر:** صفر صفوف، صفر مجلدات في الجذر، لا يصل لصور سامر المنتظرة أو المرفوضة بالاسم، ولا يرفع.
2. **مستخدم آخر:** يرى ملفه فقط، ولا شيء في مجلد سامر، ولا أرقام حسابات أخرى، وحذفه أو نقله لملفات سامر لا يغيّر شيئاً.
3. **المدير:** لا يرى شيئاً، وفحص الصحة (سرد الجذر) يعمل بلا خطأ.
4. **المالك:**
   - يسرد ملفاته الثلاثة ولا يرى غيرها؛
   - يرفع ويُعاد له الصف كما تفعل واجهة التخزين؛
   - لا يرفع في مجلد غيره.
   - **التنظيف كاملاً:** يجد الملف المرفوض والملف الجديد غير المستخدم ويحذفهما (مع إعادة الصفوف)، وتبقى الصورة المعتمدة والمنتظرة، ولا يُمس ملف غيره.
5. **حراسة:**
   - الـ bucket عام؛
   - سياسة قراءة واحدة فقط هي سياسة المالك؛
   - **لا سياسة قراءة مفتوحة للزائر أو للجميع**، وهذا يفشل لو أعادتها migration لاحقة.

## 6. ما يجب التحقق منه على staging بعد التطبيق

- **قراءة فقط قبل التطبيق:** هل دوال السرد في Supabase Storage تعمل بصلاحية المستدعي، فتطبَّق عليها السياسة؟ هذا هو السلوك المتوقع، لكن يُتحقق منه من `pg_proc` بموافقتك.
- **بعد التطبيق:**
  - سرد بمفتاح الزائر يعيد قائمة فارغة؛
  - سرد مستخدم لمجلد غيره يعيد قائمة فارغة؛
  - S10 وS10b (فحص التخزين بجلسة المالك) وS11 تنجح؛
  - صفحة الصحة تبقى «متاحة».

## 7. ما لا يغطيه هذا الإصلاح

رابط ملف معروف ما زال يُفتح علناً، وهذا يشمل الصورة المنتظرة إن تسرّب رابطها. التحليل والخيارات في `PHASE-6-PENDING-PHOTOS.md`.
