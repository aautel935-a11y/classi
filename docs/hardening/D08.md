# D-08 — dispatch functions, OTP outbox, push text, login enumeration, sign-out everywhere

Branch `hardening/d08`. Covers the audit gaps TM-13 (critical), TM-14, TM-12, TM-06 and TM-21.
Nothing here has been applied to any hosted database or deployed. Each hosted step below needs its own approval.

## What changed

| Gap | Before | After |
|---|---|---|
| TM-13 (critical) | `claim_push`, `claim_otp`, `log_sms`, `drop_push_subscriptions` were executable by `anon`, gated only by `dispatch_secret`; `claim_push` returned the VAPID private key. Anyone holding the secret could read every waiting OTP and every notification. | New `worker_*` functions, executable by `service_role` only (SECURITY DEFINER, `search_path = public, pg_temp`). The two routes call them with `SUPABASE_SERVICE_ROLE_KEY` (server env only). The secret now only proves the wake-up came from the database (`worker_wake_ok`). Step B removes the old anon functions. |
| TM-14 | OTP kept in its own `otp` column, no expiry; email fallback to any email on the account. | Codes older than 5 minutes are deleted, never handed over; handed over once (deleted on claim); fallback only to a **confirmed** email, never on a phone change; step B drops the `otp` column (the code is read from the SMS text). |
| TM-12 | Web Push carried the notification body (names, times, amounts) to the push service and the lock screen. | Push carries a neutral line by kind (`lib/push-text.ts`), title "Classi" and a link; the details open in the app. |
| TM-06 | Login said "number not registered". | An unregistered number gets the same code screen and wording as a registered one. |
| TM-21 | Sign-out only on this device. | "أخرجني من كل الأجهزة" on the account page (`signOut({ scope: "global" })`). |

Build guard (`lib/deploy-guard.ts`): the build fails if a `NEXT_PUBLIC_*` variable holds a service/secret key, or if `SUPABASE_SERVICE_ROLE_KEY` is not the secret key of the same project as `NEXT_PUBLIC_SUPABASE_URL`. A missing key is allowed (the routes fall back to the old path until step B) and is reported by `/api/health` (`worker` check) and in the build summary (`worker-key=missing`), never the value.

## Rollback

- After B: `rollback_20261114010000_d08_enforce.sql` restores the old functions and the column (state = after A, checked byte-for-byte in tests).
- After A: `rollback_20261114000000_d08_workers.sql` restores the state before D-08.
- Code: redeploy the previous staging deployment. Before B the old code still works; after B, roll back B first.

## Remaining risks

- TM-06: an attacker calling the auth API directly can still tell registered numbers apart; mitigated by Turnstile and rate limits.
- SMS reminder text is still detailed (TM-12 covered push only).
- The service-role key bypasses RLS: it is confined to two routes by the CI guard; rotate it if it ever leaks.
